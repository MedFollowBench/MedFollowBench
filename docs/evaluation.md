# 评测说明

## 单轮评测

- 输入：`patient_profile`、`flow_requirements`、`information_nodes` 及 `conversation.messages` 中的历史对话与当前患者回复。
- `prompt_components.history` 与 `current_patient_reply` 是另一种上下文表示；构造输入时避免与完整 messages 重复拼接。
- 输出：下一轮医生回复。
- `main_behavior_type` 等行为标签可用于分组分析；是否作为被测模型输入需要按实际实验协议确认。
- 当前不包含独立的标准医生答案；不据此直接使用依赖参考答案的评分方法。
- 已有内容质量与提问合理性评测提示词，但裁判版本、参数、失败处理和最终聚合口径待补齐。

## 多轮评测

- 输入：`patient_profile`、`information_nodes`、`detailed_flow_requirements` 和完整流程。
- 输出：完整医生／患者对话。
- 250 条空画像保留为空字符串，不自动补造画像。涉及未知患者事实的回答策略尚待实验负责人确认。
- 患者模拟器原始提示词为空；患者模型、医生可见信息、开场、结束、最大轮数和重复运行配置未确定前，不提供假定的完整运行实现。

## 已有流程完整性判定

`prompts/evaluation/多轮流程完整性.txt` 是从历史评测内容提炼的版本，不是恢复的原始提示词。输入为患者画像、信息节点、精细流程要求和完整对话；输出包括：

```json
{"模型分析": "按节点说明判断过程", "是否有遗漏": "有", "遗留问题": ["遗漏节点说明"]}
```

这是对话级“是否存在遗漏”的判定。节点覆盖率需要额外的逐节点判定与分母定义，不能直接从此二分类输出推得。是否计算无遗漏率、如何处理失败样本、是否按病种加权，需与论文实际实验一致后实现。

## 提示词使用

医生与部分评测提示词来自具体模型输入，包含原病例上下文。保留原文用于溯源；正式运行前需确认字段替换边界，避免将原病例信息带入其他病例。患者提示词缺失，不能将空文件当作可运行模板。新编写的协议应明确标为新版本，不宣称复现未知的历史设置。
